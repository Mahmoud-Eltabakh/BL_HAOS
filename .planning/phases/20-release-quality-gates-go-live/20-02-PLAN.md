<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Operator workstation -> HAOS Supervisor/API | Environment credentials and mutation commands cross into the live host. |
| Candidate image/config -> running HAOS add-on | Upgrade and rollback change privileged container state and host-integrated services. |
| Live runtime -> release evidence | Runtime responses, logs, identifiers, URLs, and credentials may be copied into retained artifacts. |
| Evidence directory -> go-live decision | Machine and human reviewers rely on evidence to approve publication. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-20-05 | Spoofing | HAOS preflight and candidate identity | high | mitigate | Resolve the add-on slug from authenticated Supervisor metadata, record version/architecture/image identity, and reject mismatched or absent identity evidence. |
| T-20-06 | Tampering/Elevation | upgrade and rollback rehearsal | critical | mitigate | Use the existing `--apply` mutation gate, read-only preflight, explicit known-good target, bounded operations, backup/version capture, and post-operation health/native verification. |
| T-20-07 | Information disclosure | evidence collection and readout | high | mitigate | Keep HA_TOKEN process-only, reject token/bearer/raw-frame/private-media material in the validator, and retain only redacted diagnostics and bounded logs. |
| T-20-08 | Denial of service | failed candidate and recovery | high | mitigate | Define a stop/rollback trigger, bounded waits, operator ownership, and HOLD/NO-GO outcomes when health, reports, or rollback verification cannot complete. |
| T-20-09 | Repudiation | release decision | medium | mitigate | Require timestamped command results, artifact manifest, candidate identity, owner, blocker disposition, and human sign-off in the readout. |
| T-20-SC | Tampering | release evidence/tool dependencies | high | mitigate | Run the evidence validator from the pinned project environment and preserve its exit status; do not introduce an unreviewed package for the release lane. |
</threat_model>
