<decisions>
## Locked Decisions

D-01 **Reuse, don't fork.** One React `MediaPanel`; the final card-only UI renders it with `.neu-page{height:auto;min-height:0;overflow:visible}`, a block host, no viewport-height card root, and confirmation dialogs sized with `max-height:min(90vh,640px)`-style values verified at 375/768/1440. A thin `MediaCardElement` owns the Lovelace contract and shared mount/`hass` lifecycle. No iframe, copied components, duplicate functional UI, or legacy panel element.
D-02 **Card contract.** Element `bl-haos-media-card` (Lovelace `type: custom:bl-haos-media-card`). `setConfig(config)`: reject non-object; accept `{type, initial_view?: 'library'|'browse'}`, throw `Error` for unknown `initial_view`; unknown extra keys ignored. `hass` setter, `getCardSize()` => 8, `getGridOptions()` => `{columns:12,min_columns:6,rows:'auto'}`, static `getStubConfig()` => `{}`. `disconnectedCallback` unmounts the root (re-mount on reconnect) - cards are reattached often by Lovelace.
D-03 **Discoverability.** On module evaluation, push once (dedupe by `type`) to `window.customCards`: `{type:'bl-haos-media-card', name:'BL-HAOS Media', description:..., preview:false, documentationURL:<integration README URL>}`. Guard `customElements.get` for both elements (module may evaluate twice).
D-04 **Module loading via HA frontend API, not Lovelace resources.** On first owner, after the static route exists, call `frontend.add_extra_js_url(hass, f"{PANEL_URL}?v={manifest version}")` (module/ES2015+, loaded by the HA frontend on every session, including Add-card picker, storage AND YAML dashboards). Last release calls `frontend.remove_extra_js_url` with the exact same URL. The integration creates NO Lovelace resource and never touches `.storage/lovelace*`; hence no duplicate-resource risk. The version query busts caching (route stays `cache_headers=False`). Do not use `panel_custom` for the card.
D-05 **Failure ordering (fail-closed).** `acquire` order: copy bundle -> register static route once -> `add_extra_js_url` (track `extra_js_registered`) -> add owner. Any exception (including CancelledError) rolls back extra URL then bundle, re-raises; `route_registration_failed` semantics unchanged (ConfigEntryNotReady). Multiple entries: shared owner set; extra URL added once, removed on last release; second entry never re-registers. Unload while another entry remains keeps URL+bundle. No `panel_custom` entry or `DATA_PANELS` conflict check remains. Loaded-card runtime fail-closed: when the integration is unloaded, new sessions do not load the module (URL removed, route 404); an already-open browser tab keeps the element but all WS/service calls fail with HA errors and the card shows the existing empty/unavailable states (no speakers => "no connected speaker"). Auth stays HA user session; bridge token stays in the config entry.
D-06 **Sidebar removal is gated.** Plan 38.1-01 adds the card and keeps the sidebar panel; Plan 38.1-02 removes `panel_custom` registration only after card operation is proven locally (unit/SIL/mock browser). Release 0.2.24 contains both; deployment is separately authorized and must be preceded by exact dashboard target confirmation so no UI gap exists.
D-07 **Legacy route/migration.** `/bl-haos-media` is not redirected (HA offers no supported panel alias; a redirect shim would be a second panel). After upgrade+restart HA returns its standard not-found for that path; bookmarks, the add-on "Open Media Catalog" wording and any dashboard `panel`/navigation links to `/bl-haos-media` must be repointed to the dashboard view holding the card. Panels are runtime-registered, so no storage migration or cleanup is needed; browser-hidden-sidebar preferences are harmless. Plan 02 corrects `modules/bridge/DOCS.md` to point to dashboard usage as a docs-only correction; bridge behavior, version 0.2.71, and changelog remain unchanged. Integration release/migration notes belong in the existing integration README (there is no integration CHANGELOG).
D-08 **Manual resource docs for YAML dashboards.** Because D-04 uses `extra_js_url`, YAML-mode dashboards need NO `resources:` entry. Document: (a) card YAML `type: custom:bl-haos-media-card`; (b) if a user manually also lists the module as a resource it will double-load harmlessly (idempotent `customElements.get` guards) but is unsupported; (c) a `lovelace: resources:` entry is only the manual fallback when `frontend: extra_module_url` is disabled by a custom frontend config, using the same `/api/bl_haos/catalog/bl-haos-media-panel.js?v=0.2.24`, `type: module`.
D-09 **No dashboard mutation.** No code, test or script writes dashboards. Real placement is a later, separately confirmed manual/UI action (Plan 38.1-03 checklist, executed by the main agent only after exact target confirmation and explicit authorization).
D-10 Versions: integration 0.2.24 (manifest, test_package_layout assertion, README mentions, parity gate). Bridge changes are limited to DOCS.md; no bridge version bump or changelog entry.
</decisions>
