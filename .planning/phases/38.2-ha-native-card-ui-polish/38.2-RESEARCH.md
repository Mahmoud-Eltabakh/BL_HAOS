# Phase 38.2 Implementation Research

**Scope:** Read-only inspection of the existing integration card, embedded styles, mock browser and behavior tests. No new UI library or external integration is needed.

## Evidence from the implementation

- `modules/integration/panel_ui/src/media-panel.tsx` contains the shared card application and its embedded `styles` string (currently around lines 1421–1499). It uses forced dark `color-scheme`, fixed dark `--neu-*` values, fixed accent/status colors, a viewport-height root, viewport-based dialog sizing, large shadows, and viewport media queries. Its navigation exposes Library, Browse media and Speakers; the Settings UI is within the Speakers management area rather than a fourth top-level tab.
- `modules/integration/panel_ui/src/speaker-management.tsx` supplies the speaker, adapter, per-speaker and system-settings controls. Its existing labels, status/error roles, disabled states and `callWS` actions are behavior contracts to retain while styling.
- `modules/integration/panel_ui/mock-harness.html` mounts the real `bl-haos-media-card` with mock Home Assistant state and captures playlist/queue actions. The outer dashboard cell currently imposes a `1120px` maximum and a fixed dark shell, so it needs explicit theme-token and card-width fixtures for this phase.
- `modules/integration/panel_ui/e2e/mock-catalog.spec.ts` already operates through the card shadow root, measures 44px targets/overflow/overlap, exercises catalog navigation and writes local screenshots. `e2e/playlist-library.spec.ts` provides broader interaction coverage and a local-only network guard.
- Existing unit suites are `src/media-panel.test.tsx` and `src/speaker-management.test.tsx`. Keep their action, labels, focus, errors and HA-injected-session expectations; update only stale appearance assertions and add theme/layout assertions.
- `npm --prefix modules/integration/panel_ui run build` emits `modules/integration/custom_components/bl_haos/panel_static/bl-haos-media-panel.js`; `tests/test_package_layout.py` checks the packaged artifact.
- The integration manifest currently represents deployed 0.2.25 and the bridge is 0.2.71. The requested styling work has no runtime-version or dependency requirement; rebuild the bundle without changing either version or package dependencies.

## Planning implications

Use the existing Shadow DOM card and mock `hass` boundary. Read HA theme CSS variables with light/dark-safe fallbacks, remove fixed dark/neumorphic styling and viewport-driven content sizing, and make layout respond to actual card width. Keep Library, Browse, Speakers and the Settings section present. Validate theme tokens and card widths through the mock card in each area, separately retain the 375/768/1440 viewport checks, and capture only local mock screenshots. Do not use a live Home Assistant host or perform playback, pairing, settings writes, deployment, publication or commits.
