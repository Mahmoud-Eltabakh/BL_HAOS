<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer/CI operator -> validation commands | Documentation determines which commands are treated as evidence and which environments are required. |
| Test runner -> report directory | Container exit status and generated XML/coverage files determine whether a gate is trusted. |
| CI policy -> external workflow implementation | Future workflow jobs may consume names and commands defined by the policy. |
| Live verification operator -> HAOS credentials and hardware | Manual checks use environment-provided credentials and physical Bluetooth state outside deterministic CI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-16-02-01 | Tampering | `SMOKE-MATRIX.md` and `CI-GATES.md` | medium | mitigate | Static contract tests assert canonical commands, gate identifiers, report names, and README discoverability. |
| T-16-02-02 | Spoofing | CI gate status derived from test-runner output | high | mitigate | Require successful command exit and expected JUnit/coverage artifacts; classify missing dependencies and infrastructure failures as non-passing outcomes. |
| T-16-02-03 | Denial of service | Docker SIL/deep gate prerequisites | medium | mitigate | Document KVM, Docker, config, and dependency prerequisites separately so environment failures are diagnosable rather than mistaken for test success. |
| T-16-02-04 | Information disclosure | Live verification evidence | medium | mitigate | Document environment-variable credentials and prohibit tokens, raw WebSocket frames, media URLs, and full device addresses in committed reports or tickets. |
</threat_model>
