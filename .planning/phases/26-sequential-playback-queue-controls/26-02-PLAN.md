## Compatibility and Rollback

- An older bridge that does not advertise the queue capability receives no queue command; its native entity retains the existing single-item `play_media` path and does not advertise queue-only feature flags.
- A bridge rollback or restart terminates the in-memory session and does not resume it. A newer integration must treat absent capability as unsupported rather than retrying or falling back to another speaker.
- Preserve the version-1 identity/command compatibility used by existing clients; introduce an explicit additive queue capability/contract version and reject unsupported queue versions before mutation.
- Validate compatibility with old-capability fixtures and current bridge tests. This is local rollback-contract evidence only; do not deploy, restart a live instance, or claim release readiness.
