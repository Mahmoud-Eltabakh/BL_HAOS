Define and wire the canonical runtime health state model and degraded-mode behavior for the BL-HAOS bridge, so operators and dependent clients receive honest, versioned health information during startup, dependency loss, stale BlueZ objects, reconnect churn, and shutdown.

Purpose: Phase 17's reconnect hardening depends on a shared contract. Without it, Bluetooth, PipeWire, Snapcast, playback, and API layers can each report a locally plausible but globally false healthy state.

Output: A production-quality health contract and implementation plan covering model, aggregation, dependency/lifecycle observations, deterministic speaker transitions, stale-object recovery classification, API/WebSocket publication, and SIL regression coverage.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| BlueZ/D-Bus -> backend | External system service sends object, property, and transport state that can disappear or become stale. |
| PipeWire/Snapcast subprocesses -> backend | Local privileged audio processes and their stdout/stderr determine dependency observations. |
| Backend -> Ingress/native API and WebSocket clients | Health data crosses to UI and Home Assistant consumers and must remain bounded and non-secret. |
| Reconnect tasks -> Bluetooth operations | Background concurrency can duplicate actions or race cache invalidation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-17-01 | Tampering | D-Bus object/cache observations | high | mitigate | Invalidate stale object paths, reload managed objects, classify the failure, and never mark the speaker connected without a confirmed operation/state observation. |
| T-17-02 | Denial of Service | reconnect worker scheduler | high | mitigate | Key in-flight tasks by normalized address, retain adapter locks, and test duplicate signal/tick behavior. |
| T-17-03 | Information Disclosure | health/API/WebSocket serialization | high | mitigate | Use bounded structured fields, redact credentials/URLs/raw subprocess output, and test serialized snapshots for secret leakage. |
| T-17-04 | Spoofing | dependency health probes | medium | mitigate | Keep probe results tied to the configured PipeWire/Snapcast boundaries and expose probe age/source in the contract; do not infer readiness from a process handle alone. |
| T-17-05 | Elevation of Privilege | subprocess failure details and runtime control | medium | mitigate | Preserve existing direct subprocess invocation without shells, keep health reporting observational, and avoid adding privileged control actions in this phase. |
| T-17-06 | Repudiation | lifecycle/reconnect failure events | medium | mitigate | Publish versioned lifecycle and classified failure events with timestamps, component, speaker identity, and bounded attempt metadata. |
| T-17-SC | Tampering | package installation | low | accept | No package installation is planned; existing dependencies and standard library are reused. |
</threat_model>
