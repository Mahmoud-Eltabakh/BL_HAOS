# Plan 01-02: Home Assistant Add-on Manifest & D-Bus Bootstrap Probe

## Goal

Define the Home Assistant add-on configuration manifest (`config.yaml`) strictly adhering to Home Assistant Developer specifications, and implement the startup D-Bus / hardware audit probe (`bl-haos-probe`).

## Must Haves

1. `config.yaml` contains all required Home Assistant Add-on fields: `name`, `slug`, `version`, `arch`, `init: false`, `ingress: true`, `ingress_port: 8099`, `host_dbus: true`, `full_access: true`, `udev: true`.
2. `config.yaml` options and schema validate against official Home Assistant Add-on rules.
3. `bl-haos-probe` script reliably detects whether the host system D-Bus socket (`/var/run/dbus/system_bus_socket`) exists, queries BlueZ adapter status, and prints structured JSON telemetry.
4. Python test suite validates manifest schema compliance and probe execution.

<task id="01-02-02">
<title>Implement startup D-Bus & Bluetooth hardware probe</title>
<description>
Create `rootfs/usr/bin/bl-haos-probe` (Python script):
- Probes `/var/run/dbus/system_bus_socket`
- Queries BlueZ `org.bluez` over system bus (or detects mock mode in tests)
- Enumerates available Bluetooth HCI adapters (e.g. `hci0`, `hci1`)
- Reports adapter MAC addresses, controller names, and operational state (`Powered`, `Discoverable`, `Pairable`)
- Returns exit code 0 on healthy connection with informative logging, or exit code 1 with actionable diagnosis
</description>
