<interfaces>
Plan 10-01 supplies `BLHAOSClient.async_command(address, operation, ...)` and credentialed `POST /api/native/speakers/{address}/command`; successful responses are validated native speaker records.

Home Assistant supplies `media_source.is_media_source_id(media_id)`, `media_source.async_resolve_media(hass, media_id, entity_id)`, and `async_process_play_media_url(hass, url)`. A resolved media item can carry a relative URL, so it must be processed before it crosses the container boundary.

`ConfigStore` persists `SpeakerSettings.default_volume` as 0-100. `MediaPlayerBridge` owns live playback processes and must report every accepted operation or terminal process outcome through its callback; the component client owns its one WebSocket task and speaker cache per config entry.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Home Assistant media source/TTS resolver to add-on command API | Resolved URLs can carry temporary authorization and direct the add-on decoder to retrieve media. |
| Add-on REST snapshot/WebSocket to native entity cache | Recovery records control Home Assistant availability and playback state. |
| Bluetooth/reconnect runtime to playback process supervisor | Connection transitions can terminate audio processes and change entity availability. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-06 | S | Recovery REST/WebSocket reconnect | high | mitigate | Refresh only through the credentialed native endpoints and reject records that fail address/trust/audio-sink validation. |
| T-10-07 | T | Media-source/TTS URL handoff | high | mitigate | Resolve through Home Assistant helpers, preserve only the processed URL at dispatch, and rely on Plan 10-01's strict URL and subprocess validation. |
| T-10-08 | I | Entity cache and diagnostics | medium | mitigate | Do not retain media URLs or credentials in state attributes, event payloads, or logs. |
| T-10-09 | D | WebSocket reconnect and process recovery | medium | mitigate | Maintain one bounded reconnect task, idempotent unload, fresh snapshots after reconnect, and per-speaker process cleanup on disconnect. |
| T-10-10 | R | State convergence | medium | mitigate | Use one native publication function and have entities render only validated cache records from REST acknowledgements, snapshots, and events. |
| T-10-SC | Tampering | Package installs | high | accept | No npm, pip, or cargo package installation occurs in this plan. |
</threat_model>
