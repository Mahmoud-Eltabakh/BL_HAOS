<objective>
Create the direct authenticated control path that lets a native BL-HAOS media player command the real add-on audio runtime and receive authoritative command acknowledgements.

Purpose: Fulfill NMP-05 with command execution rather than the pre-Phase-10 in-memory playback stub, while preserving Phase 9's REST/WebSocket bridge as the primary transport.
Output: A validated native command API, a client/entity command adapter, and a per-speaker FFmpeg-to-PipeWire process supervisor.
</objective>

<interfaces>
Existing native REST base path: `NATIVE_API_PATH = "/api/native"`; `BLHAOSClient` owns credential headers, cached speaker records, and listeners. `native_speaker_record(source, device)` returns the address-keyed add-on record consumed by the integration.

Existing entity contract: `BLHAOSMediaPlayer` is a `MediaPlayerEntity` with `_attr_should_poll = False`; its entity properties must remain cache-only and listeners call `async_write_ha_state()`.

Existing backend contract: `MediaPlayerBridge` exposes `get_state(address)`, `get_volume(address)`, `handle_command(address, command)`, `play_url(address, url)`, and `set_volume(address, volume)`. Replace its command-string-only boundary with a validated structured native-operation boundary while retaining the legacy MQTT caller through an adapter.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Home Assistant entity to add-on command API | Credentialed control requests can start or stop audio processes on the add-on. |
| Add-on command API to PipeWire/subprocess runtime | Untrusted media metadata and selected speaker identifiers become process arguments and audio-routing targets. |
| Add-on state to native WebSocket | Command outcomes become entity-visible state updates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | S | Native command endpoint | high | mitigate | Reuse constant-time bridge-credential verification before speaker lookup, dispatch, or acknowledgement. |
| T-10-02 | T | Command payload and subprocess launch | high | mitigate | Use Pydantic allowlists, normalized addresses, bounded volume, structured URL parsing, and argument-list subprocess execution. |
| T-10-03 | I | Command errors and logging | medium | mitigate | Return stable error classes and redact credentials plus complete signed media URLs from logs and payloads. |
| T-10-04 | D | Decoder and playback child processes | medium | mitigate | Enforce one owned process group per speaker, bounded termination, awaited reaping, and state cleanup on child exit. |
| T-10-05 | R | Playback acknowledgement | low | mitigate | Emit the normalized post-operation speaker record over REST and the existing native WebSocket channel. |
| T-10-SC | Tampering | Package installs | high | accept | The plan adds a Debian base-image package only; no npm, pip, or cargo package installation occurs. |
</threat_model>
