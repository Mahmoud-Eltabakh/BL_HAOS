## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Add-on configuration to daemon startup | An administrator's interoperability setting controls whether optional broker credentials and compatibility code are used. |
| Add-on runtime to Ingress diagnostics | Runtime state becomes user-visible diagnostic data through an unauthenticated-in-code dashboard API. |
| Custom integration runtime to Home Assistant diagnostics download | Cached bridge data is serialized into an exportable artifact. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | S | Optional MQTT activation | medium | mitigate | Default compatibility off, resolve Supervisor service credentials only after explicit configuration, and keep native startup independent of broker state. |
| T-11-02 | T | Legacy retained discovery state | medium | mitigate | Publish a bounded one-time retained cleanup only from the explicit migration path and persist completion after acknowledgement. |
| T-11-03 | I | Native diagnostics API and Ingress | high | mitigate | Return status booleans, versions, and aggregate counts only; exclude bridge/MQTT credentials, authorization headers, endpoint secrets, and media URLs. |
| T-11-04 | I | Config-entry diagnostics export | high | mitigate | Use Home Assistant `async_redact_data` and tests that inspect serialized diagnostics for secret-bearing fields. |
| T-11-05 | D | Optional broker failure | medium | mitigate | Make broker connection and cleanup best-effort, bounded, and incapable of delaying native bridge initialization. |
| T-11-SC | Tampering | Package installs | high | accept | No npm, pip, or cargo package installation is planned; the existing frontend lock/package tooling is used only for the build validation. |
</threat_model>
