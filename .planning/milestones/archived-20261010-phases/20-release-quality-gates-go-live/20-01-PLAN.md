<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner -> repository/build inputs | Workflow commands consume manifests, Dockerfiles, lockfiles, source, and test artifacts. |
| Release candidate -> published image/evidence | Build outputs and reports become operator-facing release claims and package inputs. |
| HAOS/live environment -> retained evidence | Credentials, device identities, URLs, logs, and runtime responses cross into reports. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-20-01 | Tampering | builder workflow and image matrix | high | mitigate | Pin actions and dependency audit tools already used by the builder; assert architecture/config alignment and fail on missing audit or build results. |
| T-20-02 | Spoofing/Information disclosure | release reports and live evidence | high | mitigate | Require redacted evidence, prohibit tokens/raw WebSocket frames/private URLs, and classify unredacted or missing evidence as non-passing. |
| T-20-03 | Denial of service | SIL runner and report generation | medium | mitigate | Preserve sequential execution, bounded preflight, aggregate nonzero status, required report existence, and explicit dependency/infrastructure failure states. |
| T-20-04 | Elevation of privilege | release policy and exception handling | high | mitigate | Keep native auth/redaction/security gates blocking; require named owner and expiry for any vulnerability exception with no default bypass. |
| T-20-SC | Tampering | npm/pip/container dependency inputs | high | mitigate | Retain package legitimacy and pip-audit/npm-audit/Trivy gates; no new package install is planned. |
</threat_model>
