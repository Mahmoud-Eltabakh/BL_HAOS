<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| BlueZ/PipeWire/Snapcast/runtime -> diagnostics service | Failure observations and subprocess-adjacent details cross into retained support data. |
| Backend -> Ingress, native integration, WebSocket, and exported bundle | Operational state crosses to clients and may disclose secrets or sensitive topology. |
| Lifecycle/reconnect/playback tasks -> shared telemetry history | Concurrent producers can race, duplicate, or exhaust bounded storage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-19-01 | Information Disclosure | diagnostics projection/support export | critical | mitigate | Reuse recursive Phase 18 redaction, omit sensitive fields, bound detail/collections/age/bytes, and assert token/URL/raw-payload absence in serialized tests. |
| T-19-02 | Denial of Service | event history and bundle generation | high | mitigate | Use fixed entry, age, detail, and serialized-byte limits; generate exports from a snapshot and never stream uncontrolled logs. |
| T-19-03 | Tampering | health-to-diagnostics projection | high | mitigate | Read only canonical HealthRegistry observations, retain contract versions, and test unavailable/degraded precedence so diagnostics cannot invent healthy state. |
| T-19-04 | Repudiation | lifecycle/reconnect/playback telemetry | medium | mitigate | Require correlation ids, timestamps, component/speaker context, stable failure class, and recovery outcome in the structured envelope. |
| T-19-SC | Tampering | dependency installation | low | accept | No package installation or dependency change is planned; existing standard-library and repository dependencies are reused. |
</threat_model>
