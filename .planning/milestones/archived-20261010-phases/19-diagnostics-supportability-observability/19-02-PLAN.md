<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Ingress/native operator -> recovery API | User-controlled action ids, targets, and auth metadata cross into privileged Bluetooth/audio operations. |
| Recovery service -> BlueZ/PipeWire/Snapcast/HA managers | Guided actions can mutate runtime state and must remain bounded, allowlisted, and concurrency-safe. |
| Demo configuration -> application startup | A test-mode switch controls whether host services are touched and must fail safe in production. |
| Backend contracts -> frontend panels | Diagnostics and recovery results cross into the browser and must stay redacted and schema-bounded. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-19-05 | Elevation of Privilege | recovery action endpoint | critical | mitigate | Require existing auth, strict action enum/target validation, fixed timeouts/attempts, and direct calls to named manager APIs only; reject command strings and arbitrary subprocess input. |
| T-19-06 | Denial of Service | repeated recovery requests | high | mitigate | Add per-target in-flight ownership/cooldown, bounded action duration, deterministic conflict responses, and correlation-linked outcome records. |
| T-19-07 | Tampering | demo mode selection | high | mitigate | Default demo off, validate named scenarios, inject demo dependencies before live initialization, and assert no host-service calls in tests. |
| T-19-08 | Information Disclosure | guidance/result/UI serialization | high | mitigate | Reuse Phase 18 redaction and Phase 19 bounded contracts; expose normalized identifiers and stable classifications only, never raw exceptions, tokens, URLs, or subprocess output. |
| T-19-09 | Spoofing | operator recovery requests | high | mitigate | Preserve native REST/WebSocket auth and do not create an unauthenticated recovery path; bind action results to correlation ids and current target state. |
| T-19-SC | Tampering | dependency installation | low | accept | No package installation or dependency change is planned; existing frontend/build dependencies are reused. |
</threat_model>
